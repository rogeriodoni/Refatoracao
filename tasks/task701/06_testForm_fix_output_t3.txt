All remaining `.Visible` references are either child-control visibility (shapes, image, buttons, labels) set independently of the form's own `Visible`, or the `TornarControlesVisiveis` recursive helper ÔÇö none depend on the form itself already being shown. The fix is scoped and safe.

**Root cause:** `InicializarForm()` (called from `Init()`, i.e. during `CREATEOBJECT`, before the harness ever calls `.Show()`) set `THIS.Visible = .T.` directly. In VFP9, once a form has been displayed, `WindowType` becomes read-only. The harness's ETAPA 3 does `loc_oForm.WindowType = 0` right before `.Show()` ÔÇö which then throws `Property WINDOWTYPE is read-only`. The sibling template `FormSIGOPCCO` (cited in this form's own comments as the pattern to follow) uses the identical `WindowType`/`ShowWindow` conditional but never sets the form's own `Visible` early ÔÇö it leaves actual showing to the caller. I removed the premature `THIS.Visible = .T.` line to match that canonical pattern; child-control visibility (already handled by `TornarControlesVisiveis` and `AjustarBotoesPorModo`) is unaffected.
