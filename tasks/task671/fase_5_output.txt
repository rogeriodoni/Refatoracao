## 1. The priority value didn't reliably reach the BO

The legacy validates in `Get_Prioridade.Valid` ÔÇö i.e. **on leaving the field**. The migration bound only `"KeyPress"` (ENTER/TAB). Going from the field straight to **Processar with the mouse** fired nothing, so `this_nPrioridade` kept its stale value while the textbox showed the new one ÔÇö `BuscarFila()` then ran the batch on a different priority than what's on screen, with no error. Fixed by:

- a single validation funnel `ValidarPrioridade()`, bound to **`"LostFocus"`** (rule #47) and still reachable from `KeyPress`;
- `BtnProcessarClick` now revalidates before using the value (textbox as single source of truth), aborting if invalid ÔÇö safe bare `RETURN`, that method has no `TRY`;
- reentrancy guard with the **wrapper + `ÔÇªExec()`** split, because the body has early `RETURN`s and clearing the flag at the end would leave it stuck at `.T.`, killing validation for the form's lifetime. Measured: two consecutive calls both return `.T.`, flag back to `.F.` each time.
- invalid input is **rejected but preserved** (`7` stays `7`), matching the legacy `Return .f.` focus-trap instead of erasing what the user typed (rule #50).
- parametrized mode is exempt ÔÇö the legacy `When` returns `.F.` there, so `Valid` never runs and the value comes from `Fortyus.Exe`; validating would pop a modal nobody sees and abort the batch.

## 2. Z-order inverted ÔÇö a transparent Shape over both buttons
