I fixed the root cause of the `CHK_4C_SELEC - Value : Data type mismatch` error in `C:\4c\projeto\app\forms\operacionais\Formsigopind.prg`.

**Root cause**: The placeholder cursor `CrSigMvCcr` created in `ConfigurarPaginaHist` wraps *all* columns in `SET NULL ON`, including `Seleciona` (the UI-only row-selection flag bound to `chk_4c_Selec` via `Column.CurrentControl`). Since this placeholder starts with zero rows, the Grid's column binding pushes a NULL value into the CheckBox's `.Value` property, which can't hold NULL ÔÇö that's what throws "Data type mismatch" during `InicializarForm`, regardless of whether `.Value` is pre-set (the previous Erro283 comment's theory about checkbox default type wasn't the actual cause).

**Fix**: Declared `Seleciona N(1) NOT NULL` in the `CREATE CURSOR` statement, overriding the `SET NULL ON` wrapper for just that column. This is safe and faithful to actual usage ÔÇö `Seleciona` is a synthetic UI tracking column, not a DB field, and every real data-population path (`ExecutarConsultaSaldo`) always writes it as a literal `0 AS Seleciona`, never NULL.

I also corrected the misleading explanatory comment at the checkbox creation site so future maintainers don't re-attribute this to the wrong cause.
