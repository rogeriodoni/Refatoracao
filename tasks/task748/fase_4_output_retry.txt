## Real defects found while auditing, and fixed

While checking whether the gate was even satisfiable, four genuine bugs surfaced ÔÇö none of which any gate would have caught:

1. **`ZAP` would freeze the form.** `SET SAFETY` is scoped per data session and this form is `DataSession = 2`, so `main.prg`'s `SET SAFETY OFF` never reaches it. I measured `SET("SAFETY") = ON` inside the private session: both `ZAP` sites would have opened a modal *"Zap ÔÇª Are you sure?"* with no visible window. Both now go through a guarded `EsvaziarCursorProdutos()`.
2. **Sorting sent the grid to EOF.** `ReordenarGrade` restored the row with a partial `SEEK` on the active tag, but five of the six tags are composite (`dpros+cpros`, ÔÇª) and `config.prg` sets `SET EXACT ON` ÔÇö the seek would fail *every time*, silently. Now transcribes the legacy `Recno()` / `Go lnRec` pair, with the `GO` placed **after** the first `Refresh` as the legacy does (the grid re-syncs the pointer when it repaints, so the original order lost the record).
3. **`SetFocus` during `Init`.** `ConfigurarGrid` called the header handler, which focused a column while `THIS.Visible` was still `.F.` ÔÇö the `TRY` would have swallowed it into an error dialog. Focus is now conditional on `THIS.Visible`.
4. **`CarregarDados` was PROTECTED.** `TesteAutomatico.prg:876` calls it from outside by macro, and the `PEMSTATUS(ÔÇª,5)` it guards with returns `.T.` for protected methods too ÔÇö the harness would enter the branch and die with *"Property CARREGARDADOS is not found"* (rule #3). Now PUBLIC.

Also: `img_4c_Imagem.Visible` no longer contradicts `TornarControlesVisiveis`, `ConfigurarImagem` moved earlier to match the SCX z-order (`Shape3` is the first object in the legacy tree), the SQL-failure message now uses the legacy wording, and the BO's `Processar` got its missing `loc_oErro` declaration.
