The four main CRUD event handlers are added to `FormUSA.prg`:

- **`BtnIncluirClick()`** ÔÇö calls `NovoRegistro()`, clears fields, sets mode to `INCLUIR` before enabling fields (per CLAUDE.md #19), enables Confirmar, navigates to Page2.
- **`BtnAlterarClick()`** ÔÇö reads `cidchaves` (PK, hidden from the grid) from the selected row in `cursor_4c_Dados`, loads via `CarregarPorCodigo()`, calls `EditarRegistro()` afterward (resets `this_lNovoRegistro` per CLAUDE.md #22), enables fields, navigates to Page2.
- **`BtnVisualizarClick()`** ÔÇö same lookup/load, but leaves the record in read mode: disables the editable fields and the Confirmar button.
- **`BtnExcluirClick()`** ÔÇö confirms via `MsgConfirma()` (logical, not numeric ÔÇö CLAUDE.md #7), reloads the record into the BO, calls `Excluir()`, and only shows an error if the BO hasn't already reported one (`this_lErroExibido` ÔÇö CLAUDE.md #20), then refreshes the list.

All four are declared `PUBLIC` (no `PROTECTED`) matching the existing `BtnConfirmarClick`/`BtnCancelarClick` pattern, since they're wired via `BINDEVENT` from `ConfigurarPaginaLista()`. No `TRY/CATCH` was needed since none of these use bare `RETURN` inside one ÔÇö consistent with the sibling handlers already in the file.

One thing worth flagging: this phase's scope was limited to these 4 methods, so I didn't touch `BtnConfirmarClick` ÔÇö the legacy duplicate-check logic (`ChkRegister` on `usuars` for INSERIR, from `comportamento.json`) isn't implemented there yet. That may be worth picking up in a later phase if it's not already covered.
