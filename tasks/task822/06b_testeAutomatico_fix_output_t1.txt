Fixed. Summary:

**Root cause**: `TesteAutomatico.prg`'s "Instanciacao" test does `CREATEOBJECT("FormSigOpZom")` with no arguments. `FormSigOpZom.Init()` passes through to `InicializarForm()`, which requires a valid `pArquivo` (image file) ÔÇö matching the production behavior of the legacy `SIGOPZOM.Init`. With no file passed, `ValidarArquivoImagem()` rejected it (`motivo="AUSENTE"`), so `InicializarForm()` returned `.F.`, causing the whole `Init()` chain to return `.F.` and `CREATEOBJECT` to yield a logical `.F.` instead of an object ÔÇö the "CREATEOBJECT retornou valor nao-objeto" failure.

**Fix** (matches the established `gb_4c_ModoTeste`/`gb_4c_ValidandoUI` bypass pattern used elsewhere in this project):
- `InicializarForm()`: added `loc_lBypassValidacao` check; the "arquivo ausente/extens├úo inv├ílida" rejection branch is now skipped when running under test/UI-validation mode, so the form fully builds its visual structure and returns `.T.` ÔÇö while production behavior (both flags `.F.`) is byte-for-byte unchanged.
- `AplicarParametros()`: guarded the `.Picture` assignment with `!EMPTY(...) AND FILE(...)` so that under the bypass (empty file param), it doesn't attempt to set an invalid/empty Picture path (per CLAUDE.md rule #25 ÔÇö silent failure risk).
- Deleted the stale `formsigopzom.FXP` / `sigopzombo.FXP` compiled files so the next run recompiles from the corrected source.

No business logic, schema, or UX behavior was changed ÔÇö the legacy "no file ÔåÆ dialog doesn't open" rule still applies in real usage.
