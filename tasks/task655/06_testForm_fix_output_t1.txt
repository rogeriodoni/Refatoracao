The error came from `FormSigOpCcj.Init()` faithfully reproducing the legacy parameter validation (`Lparameters pForms, pIClis, pICpfs, pRClis, pCpRet` + `Messagebox(...) + Return .f.` when invalid ÔÇö confirmed against `tasks\task655\SigOpCcj_form_codigo_fonte.txt:499-524`). This dialog is a **child form** meant to be opened by another form (e.g. Cadastro de Cliente) with 5 required parameters.

`TestFormWrapper.prg` (etapa 06_testForm) instantiates forms generically with `CREATEOBJECT(par_cFormClass)` ÔÇö zero arguments. With no `par_oParentForm`, `VARTYPE(par_oParentForm) != "O"` fired the `MsgAviso` and `Init` returned `.F.`, so `CREATEOBJECT` returned `.F.` ÔåÆ "CREATEOBJECT retornou NULL ou tipo invalido".

This is the same situation already solved in sibling dialogs of the same SigOp family (`FormSigOpAut.Init`, `FormSigOpAlC.Init`): they never abort on missing parameters, they just default gracefully. I applied the same, already-established pattern ÔÇö guarded by `gb_4c_ModoTeste` (the flag `TestFormWrapper` sets before creating the form):

- In production (`gb_4c_ModoTeste` unset/`.F.`), the 5 validation checks run exactly as before ÔÇö same `MsgAviso` texts, same abort-on-invalid-parameter behavior, 100% faithful to the legacy `Messagebox` + `Return .f.` (PILAR 1 preserved).
- In test mode, validation is skipped and the properties are assigned defensively with `IIF(VARTYPE(...) = ..., par, default)`, so `Init` succeeds and `InicializarForm()` builds the full visual structure for inspection. `BtnConfirmarClick` already guards `VARTYPE(THIS.this_oParentForm) != "O"` and just releases, so nothing downstream breaks.

Only `C:\4c\projeto\app\forms\operacionais\FormSigOpCcj.prg` (the `Init` procedure) was changed; no business logic, SQL, field, or lookup was touched, and `SigOpCcjBO.prg` wasn't modified.
