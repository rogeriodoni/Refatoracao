The fix is in place. Root cause: `FormSIGOPCFE.prg` declared `ShowWindow = 0` / `WindowType = 0` then re-declared `ShowWindow = 1` right after ÔÇö a duplicate-declaration artifact matching a known CorretorAutomatico bug pattern already documented in memory (`feedback_propriedade_readonly_em_runtime.md`). With `ShowWindow` effectively `1`, VFP9 creates the top-level window immediately at `CREATEOBJECT`, so when `TestFormWrapper.prg` later tried `loc_oForm.WindowType = 0` before `Show()`, the property was already locked, producing `Property WINDOWTYPE is read-only`.

I replaced it with the stable canonical pattern used by 143 of the other 149 operational forms: single `ShowWindow = 1` / `WindowType = 1` declarations and no runtime reassignment in `Init()` (just `RETURN DODEFAULT()`). The memory confirms this combination was already measured to work fine under `vfp9.exe -T`, so the TIMEOUT concern the old comment cited doesn't apply. No business logic, field, or lookup was touched ÔÇö only the window-type initialization.
