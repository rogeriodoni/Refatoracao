## What I found

The prior (sonnet) attempt was **right that the 4 CRUD handlers don't apply here**, but wrong to stop there ÔÇö it made zero edits, which the orchestrator's no-op detector (Erro178) correctly treats as a failed phase.

`SIGPRCPR` is a modal child dialog: `Class: form` (not `frmcadastro`), no `Grupo_Op`, no `pcEscolha`, exactly 3 standalone buttons (Sair/Ok/Conferencia). Inventing `BtnIncluirClick`/etc. would violate PILAR 1. The Phase 7 gate agrees ÔÇö I replicated its logic: `legadoSemCrud=True, nBotoesLegado=3, nHandlers=3, min=2` ÔåÆ **PASSA**.

But three legacy **events** were genuinely missing, so the phase did have real work:

1. **`Get_Leitura.When` = `Set Confirm On` / `.LostFocus` = `Set Confirm Off` ÔÇö dropped entirely.** With VFP's default `CONFIRM OFF`, the barcode TextBox (`InputMask = "99999999999999"`, 14 digits) **auto-exits on the 14th digit**, so the scanner's trailing ENTER leaks to whatever control took focus. That's the core workflow of this screen. Added `LeituraWhen`/`LeituraLostFocus` via `BINDEVENT`, matching the project idiom (`FormFti`, `Formsigprdft`).
2. **The legacy `Valid` fires on *any* field exit; the migration only bound `KeyPress` (ENTER/TAB).** Typing a barcode and clicking Ok with the mouse silently discarded the read. `LeituraLostFocus` now covers that, with a reentrancy guard (`this_lProcessandoLeitura`) since `MsgAviso` + `SetFocus` re-trigger `LostFocus`.
3. **`SET CONFIRM OFF` in `Destroy`** ÔÇö this form has no `DataSession = 2`, so the setting would leak into the rest of the app if closed with focus in the field.
