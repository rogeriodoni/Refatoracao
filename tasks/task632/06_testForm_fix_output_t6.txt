Fixed. The `OR` was eagerly evaluating `CarregarParametros()` regardless of test-mode flags, since VFP9's `OR` has no short-circuit ÔÇö so in headless/automated test runs it always hit `SQLEXEC` and failed with "SQL Server inexistente ou acesso negado," aborting the form before it could even render. Replaced it with an explicit `IF/ELSE` that skips the SQL call entirely when `gb_4c_ValidandoUI`/`gb_4c_ModoTeste` is set, matching the documented pattern (rule #27) already used elsewhere (e.g. `FormSIGPRIMP.CarregarLista`). No business logic, schema, or UX changed ÔÇö only the guard's evaluation order.
