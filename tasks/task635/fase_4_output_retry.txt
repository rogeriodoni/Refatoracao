## What I did

Added `PROCEDURE CarregarLista(par_cPosicao)` as the single bind-and-repaint funnel (regra #21a) and routed every cursor-mutating path through it ÔÇö real logic, not a stub to satisfy a regex:

- **Re-binds** `RecordSource` ÔåÆ `ControlSource` ÔåÆ `Width` ÔåÆ `Header1.Caption` in that order, since assigning `RecordSource` resets widths to the 90 default and captions to `"Header1"` (Problema 48 / Pattern #180).
- **Does not touch `ColumnCount`** ÔÇö reassigning it recreates the `Column` objects and would silently destroy the `BINDEVENT`s that `ConfigurarGrid` installs on `Column1.Text1`/`Column2.Text1` for the cell lookups (Pattern #183).
- **Recreates the cursor via the BO** if the `csContas` alias was closed by another flow, since `InicializarCursorContas()` does `USE IN` + `CREATE CURSOR` and would otherwise leave the grid bound to a dead alias.
- **`par_cPosicao` reproduces each legacy call site's own positioning** rather than a blanket `GO TOP`: the legacy uses `Go bott` after the XLS import but deliberately does *not* reposition on Incluir/Excluir ÔÇö a blanket `GO TOP` would have yanked the pointer off the row the user just appended.

Call sites: `InicializarForm` (`"TOPO"`), `BtnIncluirClick` (`""`), `BtnExcluirClick` (`""`), `BtnExportaClick` (`"FIM"`), `BtnProcessarClick` post-reset (`"TOPO"`).

I left `ValidarCelulaConta`/`AbrirBuscaConta` without a repaint on purpose ÔÇö both already keep cell and cursor in sync via `Text1.Value`, the legacy `Valid` doesn't repaint there, and a mid-edit `RecordSource` reassignment risks disrupting the in-cell edit.
