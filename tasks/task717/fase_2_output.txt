Done. `SigOpCtsBO.prg` is a new (untracked) file, since Fase 1 created it fresh ÔÇö Fase 2 just completed it.

**What this BO actually is**: SIGOPCTS is a password-confirm/change dialog with no backing table ÔÇö it reads/writes the `Senhas` column on whatever cursor alias the caller passes in (`this_cArquivo`). Because of that, the generic "CRUD skeleton" (Inserir/Atualizar/SQL INSERT/UPDATE) doesn't apply here, matching the precedent already set by `SigOpAutBO.prg` and `sigtosenBO.prg` for the same class of dialog.

Methods added:
- **`CarregarDoCursor(par_cAliasCursor)`** ÔÇö reads the raw `Senhas` value from the given alias (or `this_cArquivo`) into `this_cSenhaArmazenada`, following the `SELECT (alias)` pattern (CLAUDE.md #9).
- **`ValidarSenhaAtual(par_cSenhaDigitada)`** ÔÇö business half of the legacy `senha.Valid`: decodes the stored password with `fCriptografar()` and compares to what was typed, setting `this_lZSen` when not in "alterar" mode.
- **`AlterarSenha(par_cSenhaNova1, par_cSenhaNova2)`** ÔÇö business half of `GetNova2.Valid`: compares the two new-password entries and, if they match, re-encodes with `fDecriptografar()` and writes it via `REPLACE`.
- **`ObterChavePrimaria()`** (PROTECTED) ÔÇö returns `this_cArquivo` for contract completeness only; never actually invoked since Inserir/Atualizar stay unoverridden.

Both `fCriptografar`/`fDecriptografar` calls are wrapped in `TRY/CATCH` and left un-stubbed per project convention (confirmed via memory + `pafBO.prg`/`SigOpAlCBO.prg` precedent) ÔÇö neither function was ever ported from the legacy Fortyus framework, and faking either one would silently corrupt password comparisons rather than fail loudly.
