## Four real defects found while verifying

I tested by exercising the handlers, not just instantiating ÔÇö which is what surfaced these:

1. **`OldValue` doesn't exist in VFP9** on `Column`, `Column.Text1`, or `TextBox` (measured: `PEMSTATUS` = `.F.` on all three). 18 sites across 4 handlers ÔÇö all pre-existing from Fases 6ÔÇô7 ÔÇö would crash the moment a user edited a quantity. Replaced with a form property captured on `GotFocus`, which is the legacy's own mechanism.
2. **`GotFocus` redirect bound to all 10 columns**, including the editable ones ÔÇö "Qtd Produ├º├úo", "Produzir Estq" and "Qtd Estoque" bounced the focus away and could never be typed into. The legacy redirects only columns 1/2/5/6/9.
3. **`Column10` (Qtd Estoque) handlers missing entirely** ÔÇö one of the two editable columns had no `Valid`. Transcribed from the dump, including the asymmetries vs. Column7 (ceiling is `Saldo - Fabrs`; the summary cursor saturates-then-subtracts instead of zero-then-adds).
4. **`SEEK` with `ALLTRIM`-concatenated keys** (rule #42) ÔÇö the padding is the key, so the lookups silently returned zero rows and the redistribution never ran.

## One judgement call worth flagging

The legacy filters the two summary grids with `SET KEY`, re-issued per row change. I measured that `SET KEY` is static (confirming it must be re-issued) but that a *partial-prefix* `SET KEY` goes empty under `SET EXACT ON`. It works here only because `DataSession = 2` leaves `EXACT` OFF ÔÇö a landmine, since the other standing guidance is to turn `EXACT` ON in private sessions. I used `SET FILTER ... ==` instead (the project's documented remedy, already used in the sibling `FormSigPrGlp`).

That change has a non-obvious consequence I had to handle: **`SET ORDER TO` clears `SET KEY` but not `SET FILTER`** (measured), and `REPLACE ALL` under a filter touches only visible rows. The legacy relies on that `Set Order To` side-effect to release the cursor before `Processar`'s global passes ÔÇö so without an explicit `SET FILTER TO`, stock reservations would have been written for only the last item the user viewed, silently. Added the explicit clear at both `REPLACE ALL Reservs` sites in the BO.
