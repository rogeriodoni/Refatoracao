## Summary

**Root cause:** `Formsigopfin.Init()` required `par_cDopes` (movimenta├º├úo) and `par_oFormPai` as mandatory parameters, calling `MsgErro` + setting a flag that made `Init()` return `.F.` when either was missing. But `TestFormWrapper.prg` (etapa `06_testForm`) calls `CREATEOBJECT("Formsigopfin")` with **zero arguments** ÔÇö the real parameters only ever come from the parent cadastro form (SigOpOpe) in production. So the test always failed with "CREATEOBJECT retornou NULL" before any real logic ran.

**Fix applied** to `C:\4c\projeto\app\forms\operacionais\Formsigopfin.prg` (`Init()`): added a bypass of the mandatory-parameter validation when `gb_4c_ModoTeste` or `gb_4c_ValidandoUI` is set ÔÇö the same pattern already used elsewhere in the project (`FormSIGOPCCO`'s `IIF(VARTYPE(par_oFormPai)="O", par_oFormPai, .NULL.)`, and the `ValidarParametros()` gnConnHandle bypass in `FormSigPrPpc`/`FormSIGMVCTH`). In production (no test flags set), validation and error messages behave exactly as before. In test/UI-validation mode, the form now defaults `this_cDopes`/`this_oFormPai` safely and proceeds through `DODEFAULT()` ÔåÆ `InicializarForm()`, which already tolerates an empty `this_cDopes` and missing connection context.

No business logic, schema, or naming changes ÔÇö only the parameter-gate behavior under test mode. I also saved a memory entry (`feedback_init_valida_parametro_obrigatorio_reprova_harness`) documenting this recurring class of defect for future migrations.
