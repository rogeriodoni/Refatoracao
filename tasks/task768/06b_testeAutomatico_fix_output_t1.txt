## Summary

**Root cause**: `ConfigurarGrade()` called `THIS.grd_4c_Grade.Column1.AddObject("chk_4c_Selecionar", "CheckBox")` immediately after `.ColumnCount = 8`, but at that exact moment VFP9 auto-binds `Column1` to whatever alias is currently selected in the work area. Since `SigOpMpdBO.Init()` ends with `SELECT crSigCdPam / GO TOP`, `Column1` auto-bound to `crSigCdPam.CuniPPads` (a `Character` field). Adding a `CheckBox` (whose `.Value` is born `Numeric`) onto a column bound to text throws `Error with CHK_4C_SELECIONAR - Value : Data type mismatch` right inside `AddObject` ÔÇö `InicializarForm` returns `.F.`, `CREATEOBJECT` returns `.F.`, and the test harness sees "CREATEOBJECT retornou valor nao-objeto". This is the exact same root cause already fixed in `FormSigOpLoc`, `FormSigOpLcZ`, and `FormSigOpLcl` (deferred-checkbox pattern).

**Fix applied** to `FormSigOpMpd.prg`:
- `ConfigurarGrade()`: removed the premature `AddObject`/`CurrentControl`/`Sparse` for `chk_4c_Selecionar`, keeping only the structural `Column1` properties.
- `ConfigurarEventosGrade()`: removed the `BINDEVENT` for the (not-yet-existing) checkbox.
- New `GarantirCheckBoxSelecionar()` (idempotent, `PEMSTATUS`-guarded): creates the `CheckBox` + its `BINDEVENT` only after `Column1.ControlSource` is bound to `TmpPends.Flag` (Logical) ÔÇö no longer assigns `.Value` explicitly, matching the sibling-form pattern.
- `CarregarGrade()`: calls `THIS.GarantirCheckBoxSelecionar()` right after the `ControlSource` binds (before the `Width`/`Header1.Caption` reassignments), replacing the old premature `CurrentControl`/`Sparse` lines.

No business logic, field, lookup, or schema changes ÔÇö scoped strictly to the runtime crash.
