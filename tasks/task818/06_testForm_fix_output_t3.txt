**Root cause**: `GarantirCheckBoxColuna()` correctly adds `Check1` to the Grid's `Column1`. But immediately after calling it, each of the 5 grid blocks in `CarregarDados()` redundantly called `.AddObject("Check1", "CheckBox")` while inside `WITH loc_oPag.grd_4c_X` (the **Grid** object, not `.Column1`). VFP9's Grid class doesn't support arbitrary `AddObject` calls on itself ÔÇö this throws `Cannot add this object to a Grid.`, which propagated up through `CarregarDados` ÔåÆ `InicializarForm`'s `TRY/CATCH`, made `InicializarForm` return `.F.`, and caused `CREATEOBJECT` to return `.F.` in the test harness (exactly matching the reported "CREATEOBJECT retornou NULL" symptom).

**Fix**: removed the stray `.AddObject("Check1", "CheckBox")` line and the 8 following redundant `.Check1.*` property lines in all 5 grid blocks (Empresas, Tipos, GrandeGrupo, GrupoProduto, Operacoes) ÔÇö the correct properties were already being set via `.Column1.Check1.*` just above, so nothing is lost functionally.

No business logic, field names, lookups, or DB schema were touched ÔÇö this was a pure structural bug in the checkbox-installation code.
