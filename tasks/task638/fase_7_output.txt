## Real defects found and fixed in the button events

1. **`CmdProcessarClick` could leave Processar permanently grey.** It disabled the button, then re-enabled it on a single trailing line with no exception protection anywhere above `ProcessarUnificacao`. The legacy repeats `This.Enabled = .t.` on *all four* exit paths precisely to prevent this. Now wrapped in TRY/CATCH with the re-enable **after** `ENDTRY`, covering the exception path too (regra #40).

2. **`ValidarProcessamento` had no TRY/CATCH.** A failure there surfaced as VFP's raw *Program Error* instead of the system dialog, and skipped the re-enable. Now protected, and it **fails closed** ÔÇö a validation that can't finish reproves, rather than letting the merge through without the legacy's three guards. No `RETURN` inside the TRY (regra #1).

3. **`REPLACE ALL` made the grid jump to the bottom** on every "Seleciona Tudo"/"Apaga Tudo". The legacy uses `Update ... Set`, which doesn't move the record pointer. Replaced with UPDATE-SQL plus explicit `RECNO()` save/restore, collapsing both handlers into one funnel `MarcarTodasAs()` ÔÇö mirroring the legacy, where both buttons genuinely share a single `Click` and the button index *is* the stored value. Used `m.par_nValor` since VFP resolves a bare identifier in SQL as a column first.

4. **`IIF(SelImp = 1, ...)`** on a cursor built under `SET NULL ON` would write `.NULL.` if `SelImp` ever arrived null, silently removing the row from the `SelImp = 1` filter forever. Added `NVL` guards here and in the validator's `COUNT FOR`.

One hypothesis I checked and **discarded**: I suspected the checkbox toggle was inverted (MouseDown vs MouseUp). The dump shows the legacy really does toggle in `MouseDown` with `MouseUp` as `NoDefault` only ÔÇö the migration is faithful, so I left it alone.
