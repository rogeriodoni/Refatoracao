## The real defect I found and fixed

`SigOpAtu` isn't standalone ÔÇö it's the dialog the **"Acerto de Invent├írio" do SIGCDBAL** opens (`SIGCDBAL_form_codigo_fonte.txt:6014-6019`):

```foxpro
Do Form SigOpAtu
If Not Used('crOpera') Or IsEmpty(crOpera.Dopes)
    && caso nao tenha escolhido a operacao cancel o processamento...
    Return
Endif
```

The dialog's output is the **row position of the caller's `crOpera` cursor** ÔÇö the caller then reads `crOpera.Dopes` (6097/6104/6154) *and* `crOpera.Estoqs` (6132). `crOpera` belongs to the caller, created filtered in its own Init (5476).

`BtnOkClick` was doing `THIS.Release()` ÔÇö destroying the form together with its BO on the same line the caller unblocked from `Show()`. `FormParaBO()` wrote into an object that died immediately. **The dialog worked on screen and returned nothing**, with no error and no log.

Fixed with the project's canonical pattern (`formbuscaauxiliar.prg:367-369` ÔÇö flag + `Hide()`, caller releases):
- `this_lConfirmado` / `this_cDopEstqSelecionado` for a migrated caller;
- `PublicarOperacaoEscolhida()` positions `crOpera` when open (the legacy channel), never creating it ÔÇö a homonymous 1-row cursor would mask the caller's filtered list;
- operation **not** in `crOpera` ÔåÆ refuses confirmation and warns, instead of leaving the caller to read whatever row the cursor was parked on (silent wrong data).

Kept faithful: the warning + close-anyway on empty field is *not* a legacy slip ÔÇö empty is precisely the caller's cancel channel.
