## What Phase 8 actually needed

The phase prompt asks for the CRUD template (`BtnBuscarClick`, `BtnSalvarClick`, `FormParaBO`/`BOParaForm`, `HabilitarCampos`, `LimparCampos`, `CarregarLista`, `AjustarBotoesPorModo`). **SIGPRGL2 has none of those in the legacy** ÔÇö it's a modal selection/processing dialog inheriting from generic `form` with exactly 4 buttons (Processar, Encerrar, apaga, SelTudo). I did not invent them; I documented each absence against the SCX evidence in a consolidation block at the top of the class.

What the form genuinely was missing:

**`CarregarDados()`** ÔÇö the tail of the legacy `Init` (filter `TmpItens` by `EmpDopNum`, `TmpCabec` to top, `Refresh`) had been dropped entirely. Without it both grids open bound but unfiltered and unpainted. Now called at the end of `InicializarForm`.

**`SincronizarBOComLinhaCorrente()`** ÔÇö the real `BOParaForm` equivalent here. Every data control is bound by `ControlSource` directly to the cursors, so VFP moves the data; but `SigPrGl2BO.CarregarDoCursor` was never called by anything, leaving `ObterChavePrimaria()`/auditoria reading blank properties. Wired into `CarregarDados` and `AfterRowColChange`, preserving the work area.

## Verification

Compiled clean, then instantiated for real (`CREATEOBJECT` in test mode) ÔÇö no exceptions, no captured dialogs, all new bindings/widths/`ColumnOrder`/props read back correct, and the BO row-sync confirmed moving with `AfterRowColChange`.

Two things the run caught that I'd otherwise have assumed:

1. **`RowHeight` read back 16, not the 17 I set.** Assigning `FontName`/`FontSize` *after* it makes VFP recompute row height ÔÇö same family as "Column.Width after RecordSource". Moved `RowHeight` below the font in both grids; now reads 17.

2. **After `CarregarDados`, items show PROD-9 while the header row is Numes=7.** I probed this rather than "fixing" it (`automation/ProbeGl2SetKey.prg`): `SET KEY TO <expr>` **freezes** the value at command time and does not re-evaluate when `TmpCabec` moves. The legacy `Init` sets the key *before* its `GO TOP`, so the legacy has the identical stale filter until the first `AfterRowColChange` realigns it. Correcting it would make the migrated tela diverge from the legada, so I kept it literal and recorded the measurement in the comment.
