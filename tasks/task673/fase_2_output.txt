**Key finding:** SIGPRSCN is a login/authentication dialog ("Libera├º├úo de Acesso ao Sistema"), not a cadastro ÔÇö the legacy code only `SELECT`s from `SigCdUsu` to validate credentials; it never `INSERT`/`UPDATE`/`DELETE`s there. So I implemented the real equivalent behavior instead of fabricating fake CRUD against a security-sensitive table:

- **`CarregarDoCursor`** ÔÇö maps the `SigCdUsu` SELECT result (`usuarios`, `senhas`) into BO properties.
- **`ObterChavePrimaria`** ÔÇö returns `Usuarios` (the table's real PK).
- **`ValidarAcesso(usuario, senha)`** ÔÇö the actual port of `SENHA.LostFocus`: queries `SigCdUsu` for an active user, compares the password via a **literal** `fCriptografar()` call (per the established project rule: this legacy hash function was never ported, and a guessed stub would silently authenticate the wrong people ÔÇö the call is left to error inside `TRY/CATCH`, surfacing `this_cMensagemErro` instead of crashing). On success it loads `SigCdPam` timeout params and calls `RegistrarAuditoria("LOGIN")`.
- **`CarregarParametrosSistema`** ÔÇö loads `ntmpchks`/`ntmpapps` from `SigCdPam`.
- **`Inserir`/`Atualizar`/`ExecutarExclusao`** ÔÇö deliberately left un-overridden (inherited `BusinessBase` refusal is correct), with a comment explaining why, since overriding them would open a write path into the users table that the legacy never had.
