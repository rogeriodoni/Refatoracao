**Root cause:** In `ConfigurarPgPgConfDesconto()`, the grid `grd_4c_GradeD` had `Column3`ÔÇô`Column6` given `.ControlSource = "cursor_4c_Tds.Campo2is"` etc. directly during `InicializarForm()` (Init time). Unlike a Grid's `.RecordSource` (which defers binding), a **Column's `.ControlSource`** resolves the alias immediately when assigned ÔÇö same class of bug already documented/fixed for `cursor_4c_Tdt` via `CriarCursorTdtVazio()`. But `cursor_4c_Tds` is only created later, inside `TbvBO.CarregarFaixasDesconto()`, which only runs when a record is actually loaded (BOParaForm) ÔÇö never during Init. So on form instantiation, VFP tried to bind `Column3.ControlSource` to a nonexistent alias and threw `Alias 'CURSOR_4C_TDS' is not found.`, which made `InicializarForm()` return `.F.` and `CREATEOBJECT` effectively fail the automated test.

**Fix:** Added `CriarCursorTdsVazio()` (mirroring the existing `CriarCursorTdtVazio()` pattern) that creates an empty `cursor_4c_Tds` with the same field list used later by `TbvBO.CarregarFaixasDesconto()`'s SELECT (per `docs/schema.sql`'s `SigOpTds` structure), and call it in `ConfigurarPgPgConfDesconto()` before the grid columns are configured. The real data still replaces this placeholder cursor later via the existing `USE IN` + `SQLEXEC` flow in `CarregarFaixasDesconto()`, so no business logic, schema, or UX changed ÔÇö only the Init-time crash is fixed.
